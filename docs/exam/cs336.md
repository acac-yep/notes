## 核心考点

### 分词

- BPE：从字符表出发，反复合并最高频相邻对，直到词表达到目标大小。
- 词表越大，序列越短（省算力/显存），但 embedding 与 softmax 参数变大，稀有 token 训练不足。
- 压缩率是判断分词器好坏的主要指标：字节数 / token 数。

### 架构

- 组件：embedding → N × (attention + FFN，前置 RMSNorm，残差) → 输出投影；位置编码常用 RoPE。
- 超参权衡：固定参数量下，深而窄 vs 浅而宽，影响训练稳定性与吞吐。
- MoE：总参数大、每 token 只激活少数专家；要区分 total params 与 active params。
- 注意力替代：线性注意力、状态空间模型减少长上下文成本，但表达能力与工程成熟度要单独评估。

### 资源账（最高频考点）

- 矩阵乘 $[m,k]\times[k,n]$ 约 $2mkn$ FLOPs。
- 训练 dense Transformer 的总 FLOPs ≈ $6ND$（$N$ 参数、$D$ token）。
- 混合精度 Adam 训练，静态显存常按每参数 12–16 bytes 估（权重 + 梯度 + FP32 master + Adam 一阶/二阶），再加激活、临时 buffer、通信 buffer。
- 算术强度 $I=\text{FLOPs}/\text{bytes moved}$；低于硬件 compute/memory 比即为 memory-bound。

### 并行

- DDP：每卡存全量参数，梯度 all-reduce。
- ZeRO-1 切 optimizer states；ZeRO-2 再切梯度；ZeRO-3/FSDP 连参数一起切，前向时 all-gather。
- TP：切单层内的矩阵（列切/行切），通信频繁，适合节点内高带宽。
- PP：按层切段，需要 micro-batch 流水，存在 bubble。
- EP：MoE 专家分散到不同设备，需要 all-to-all。
- 组合原则：先看哪个资源最先爆（显存/带宽/通信），再选切分维度。

### Scaling

- Kaplan：固定算力下偏向更大模型、更少 token。
- Chinchilla：重新拟合后认为参数与 token 应均衡增长，经验口径约 20 tokens/parameter（不是定律）。
- IsoFLOP：固定算力画不同模型大小的 loss 曲线，取包络线选最优点。
- 小规模实验拟合 → 外推大规模配置，避免盲目试错。

### 推理

- prefill：并行处理 prompt，矩阵大，偏 compute-bound。
- decode：逐 token，反复读权重与 KV cache，偏 memory-bound。
- KV cache 大小 ≈ $2 \times L \times H_{kv} \times d_{head} \times S \times B \times \text{bytes}$。
- MHA → GQA（多 query 共享 KV）→ MQA（全共享）→ MLA（压缩到 latent）：cache 递减，质量风险递增。
- 投机解码：draft 模型提候选、target 并行验证，保持目标分布时是 lossless 加速，收益取决于接受率。
- PagedAttention + continuous batching：按页管理 KV、按 token step 动态增删请求，提高吞吐但可能抬高尾延迟。

### 数据与后训练

- 数据：Common Crawl/WET 解析 → 语言过滤 → 去重（精确 + 近似）→ 质量分类 → 配比。
- 去重收益：减少记忆化与重复 token 浪费。
- SFT：模仿学习，交叉熵；RLHF：偏好数据，PPO 需要 reward model 与 KL 约束；DPO 把偏好优化改写成分类损失，省掉 RL 循环。
- RLVR：可验证奖励（数学/代码）上的 RL，常用 GRPO（组内相对优势，省 value model）。

## 公式与数字

训练算力：

$$
\text{FLOPs}_{\text{train}} \approx 6ND
$$

KV cache：

$$
\text{bytes}_{\text{KV}} = 2 \cdot L \cdot H_{kv} \cdot d_{head} \cdot S \cdot B \cdot b
$$

其中 $L$ 层数、$H_{kv}$ KV 头数、$d_{head}$ 每头维度、$S$ 序列长度、$B$ batch、$b$ 每元素字节数。

算术强度：

$$
I=\frac{\text{FLOPs}}{\text{bytes moved}}
$$

速记数字：

| 项 | 数值 |
|---|---|
| 训练 FLOPs | $6ND$ |
| 每参数训练显存 | 12–16 bytes（混合精度 Adam） |
| Chinchilla 经验配比 | ~20 tokens / parameter |
| 矩阵乘 FLOPs | $2mkn$ |
| KV cache 元素数 | $2 L H_{kv} d_{head} S B$ |

## 高频题型

1. **给定参数量与 token 数估训练算力**
   先算 $6ND$，再除以 GPU 有效算力（峰值 × 利用率）得卡时。
2. **给定 GPU 数估可训练模型规模**
   先算总显存（卡数 × 容量），扣掉激活与碎片后除以 12–16 bytes/参数。
3. **判断算子瓶颈**
   算算术强度，与硬件 FLOPs/带宽比比较；decode、归一化、逐元素算子通常 memory-bound。
4. **选并行方案**
   列出显存瓶颈项（参数/梯度/优化器/激活），对照 ZeRO-1/2/3、TP、PP 的切分对象与通信量。
5. **算 KV cache 显存**
   套上面公式；再算 batch 上限（剩余显存 / 每序列 KV）。
6. **拟合 scaling law**
   固定算力扫模型大小，取 IsoFLOP 最优点；或对小规模点拟合幂律外推。

## 易错点

- $6ND$ 是总 FLOPs，不是时间；利用率、通信、launch 开销没算进去。
- 只按 2 bytes/参数估显存，漏掉梯度、优化器状态、激活。
- 混淆 total params 与 active params（MoE）。
- 以为 decode 慢是因为 FLOPs 多——实际常被权重与 KV 读取卡住。
- 把 Chinchilla 的 20 tokens/param 当成固定定律。
- 忽略 activation checkpointing 是「用算力换显存」，会抬高训练时间。
- 用 benchmark 分数直接推真实能力，忽略污染与成本。

## 一页速记

- 训练算力 $6ND$；矩阵乘 $2mkn$。
- 混合精度 Adam：每参数 12–16 bytes。
- 算术强度决定 compute-bound / memory-bound。
- ZeRO-1 优化器、ZeRO-2 梯度、ZeRO-3 参数。
- TP 切层内、PP 切层间、EP 切专家。
- prefill 算力型，decode 访存型。
- KV cache 随 $L, H_{kv}, S, B$ 线性增长。
- GQA/MQA/MLA 都是拿质量换 cache。
- 投机解码 lossless 的前提是严格保持目标分布。
- Chinchilla ≈ 20 tokens/param，但取决于数据与目标。
- SFT 模仿、RLHF 偏好、RLVR 可验证奖励。
- 数据去重省的是重复 token 的训练算力。
