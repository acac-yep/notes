# 第 2 章 词法分析

## 学完要会什么

你要能把源程序切成 token，能用正规式描述 token 模式，能把正规式转换为 NFA，再转换为 DFA，并能对 DFA 做化简。

## 词法记号、模式、词法单元

三个概念要分清：

- 词法记号 token：语法分析器看到的类别，如 `id`、`num`、`if`、`+`。
- 模式 pattern：描述某类 token 的规则，如标识符是“字母开头，后接字母或数字”。
- 词法单元 lexeme：源程序中实际出现的字符串，如 `count`、`123`。

词法分析器通常输出：

```text
(token_name, attribute_value)
```

例如 `int* (*(*b)[10])[10];` 的记号流可写成：

```text
int  *  (  *  (  *  id:b  )  [  num:10  ]  )  [  num:10  ]  ;
```

## 正规式

正规式用于描述正规语言。常用运算：

- 并：`r|s`，表示属于 `r` 或 `s`。
- 连接：`rs`，表示先匹配 `r` 再匹配 `s`。
- 闭包：`r*`，表示重复 0 次或多次。
- 正闭包：`r+`，表示重复 1 次或多次。
- 可选：`r?`，表示 0 次或 1 次。

常见 token 正规式：

```text
letter = A|...|Z|a|...|z
digit  = 0|1|...|9
id     = letter (letter|digit)*
num    = digit+ (. digit+)? (E (+|-)? digit+)?
```

## 有限自动机

NFA 和 DFA 都识别正规语言。

DFA 特征：每个状态遇到每个输入符号最多只有一条确定转移，没有 epsilon 转移。

NFA 特征：同一状态遇到同一输入可以有多条转移，也可以有 epsilon 转移。

NFA 更容易从正规式构造，DFA 更适合实现词法分析器。

## NFA 到 DFA：子集构造法

核心思想：DFA 的一个状态对应 NFA 的一组状态。

步骤：

1. 从 `epsilon-closure(start)` 得到 DFA 初态。
2. 对每个 DFA 状态集合 `T` 和输入符号 `a`，计算 `epsilon-closure(move(T, a))`。
3. 如果得到的新集合没出现过，就作为新 DFA 状态加入。
4. 包含 NFA 终态的 DFA 状态就是 DFA 终态。

记住两个函数：

```text
move(T, a)：从 T 中任一状态读 a 能到达的状态集合
epsilon-closure(T)：从 T 出发只走 epsilon 边能到达的状态集合，含 T 本身
```

## DFA 化简

目标：合并等价状态。两个状态等价，意思是从它们出发对任何后续输入，要么都接受，要么都拒绝。

常用分割法：

1. 初始划分为终态集合和非终态集合。
2. 对每个分组，检查其成员在同一输入下是否转向同一分组。
3. 若不同，继续细分。
4. 直到不能再细分。

## 词法分析器生成器

Lex/Flex 类工具通常接收“正规式 + 动作代码”，生成扫描器。扫描器用最长匹配原则选择词法单元；若多个规则匹配同样长的串，通常选择先出现的规则。

例如关键字和标识符冲突时：

```text
if      return IF;
[A-Za-z][A-Za-z0-9]* return ID;
```

因为 `if` 规则写在前面，所以 `if` 被识别为关键字，不是普通标识符。

## 典型题型

1. 写某段 C 代码或声明的 token 流。
2. 为标识符、数字、注释、邮箱等写正规式。
3. 由正规式画 NFA。
4. 由 NFA 构造 DFA。
5. 对 DFA 做最小化。
6. 判断词法错误，例如非法字符、未闭合字符串。

## 易错点

- 关键字通常可先按标识符识别，再查关键字表，也可以规则优先处理。
- `*` 在正规式中表示闭包，在 C 声明里是指针，在词法中只是一个运算符或界符，语境不同。
- 最长匹配优先于规则先后。规则先后只在同样长时起作用。
- epsilon-closure 一定包含原状态本身。

## 自测清单

- 能否写出 `int* (*(*b)[10])[10];` 的 token 流？
- 能否把 `letter(letter|digit)*` 转成自动机？
- 能否解释 NFA 与 DFA 的区别？
- 能否手算一个小 NFA 的子集构造表？
