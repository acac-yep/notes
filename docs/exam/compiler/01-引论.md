# 第 1 章 引论

## 学完要会什么

你要能画出编译器各阶段，解释每一阶段输入、输出和作用，并能用一个简单赋值语句说明 token、语法树、语义检查、中间代码、目标代码之间的关系。

## 编译器的基本阶段

编译器通常分为前端和后端。

前端关心源语言，后端关心目标机器：

```text
前端：词法分析 -> 语法分析 -> 语义分析 -> 中间代码生成
后端：代码优化 -> 目标代码生成 -> 机器相关优化
```

典型例子：

```c
position = initial + rate * 60
```

词法分析把字符流切成 token：

```text
(id, position) (=) (id, initial) (+) (id, rate) (*) (num, 60)
```

语法分析识别表达式结构，例如 `rate * 60` 优先于加法。语义分析检查 `position`、`initial`、`rate` 是否声明，类型是否能参与加法、乘法和赋值。中间代码可能生成：

```text
t1 = int_to_real(60)
t2 = rate * t1
t3 = initial + t2
position = t3
```

优化阶段可能删除冗余转换、合并临时变量。代码生成阶段再把中间表示转成目标机器指令。

## 符号表

符号表保存名字的信息，是全程共享的数据结构。

常见字段包括：

- 名字：如 `position`。
- 种类：变量、函数、类型名、字段、标签。
- 类型：`int`、`real`、数组、函数类型等。
- 作用域：全局、局部、嵌套块。
- 地址信息：偏移量、静态区位置、栈帧位置、寄存器位置。

词法分析器发现标识符后通常会查或插入符号表；语义分析补充类型和作用域；代码生成查询地址和偏移。

## 编译器和解释器

编译器先翻译再执行，解释器边读边执行。

编译器优点是运行快、能做全局优化；解释器优点是交互性强、移植容易、调试方便。现代系统常混合二者，例如 Java 先编译成字节码，再由虚拟机解释或即时编译。

## 编译系统不只包含编译器

一个 C 程序从源文件到运行通常经历：

```text
预处理器 -> 编译器 -> 汇编器 -> 链接器 -> 装入器
```

预处理器处理 `#include`、宏替换和条件编译。编译器生成汇编。汇编器生成目标文件。链接器合并目标文件和库，解析外部符号。装入器把可执行文件放入内存并启动。

## 典型题型

1. 给出语句，写词法记号流。
2. 说明编译器各阶段的输入和输出。
3. 判断某个错误在哪个阶段发现：拼错非法字符是词法错误；括号不匹配是语法错误；未声明变量或类型不匹配是语义错误。
4. 解释编译器、解释器、汇编器、链接器、装入器的区别。

## 易错点

- token 不是字符，也不是字符串本身，而是“种别 + 属性值”的二元组。
- 语法正确不代表语义正确，例如 `int x; x[3] = 1;` 语法可能能过，但类型检查会失败。
- 优化必须保持语义等价，不能只看指令更少。
- 符号表不是某一阶段独有，而是多阶段共享。

## 自测清单

- 能否从字符流一路说到目标代码？
- 能否解释为什么乘法优先级属于语法分析问题？
- 能否说明未声明变量为什么不是词法错误？
- 能否解释 C 程序为什么还需要链接？
