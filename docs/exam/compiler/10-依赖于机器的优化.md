# 第 10 章 依赖于机器的优化

## 学习定位

本章在教材中属于加星号的进阶内容。主线课程若时间有限，可只掌握基本概念：机器相关优化会利用具体处理器结构、寄存器、流水线、缓存和并行性。

## 处理器体系结构相关因素

机器相关优化关注：

- 指令流水线。
- 分支延迟和分支预测。
- 多指令发射。
- 寄存器数量和类别。
- 缓存局部性。
- 数据相关和控制相关。

机器无关优化让中间代码更好；机器相关优化让目标代码更贴合硬件。

## 代码调度

代码调度通过调整指令顺序减少流水线停顿。

例如：

```asm
LD  R1, a
ADD R2, R1, R3
```

如果加载后立刻使用 `R1` 会产生等待，可在中间插入与 `R1` 无关的指令。

调度必须保持依赖关系：

- 数据相关：后一条指令使用前一条结果。
- 控制相关：指令是否执行依赖分支。
- 资源相关：同一硬件资源不能同时使用。

## 基本块调度

基本块内部没有分支，适合做局部调度。调度常先构造数据依赖图，节点是指令，边表示必须先后执行。

合法调度是依赖图的拓扑序。好的调度还要减少停顿和资源冲突。

## 全局代码调度

全局调度跨基本块移动代码，收益更高，风险也更高。移动指令时必须保证不会改变异常、内存访问、副作用和控制流语义。

例如把循环中的不变计算移到循环前，是机器无关优化；但把某条加载提前到分支前，可能引入原本不会发生的异常，需要谨慎。

## 软件流水

软件流水用于循环，把不同迭代的指令交错执行，提高流水线利用率。

直觉：

```text
第 i 次迭代做加载
第 i-1 次迭代做计算
第 i-2 次迭代做存储
```

它需要处理循环启动、稳定阶段和收尾阶段。

## 数据局部性优化

缓存友好代码通常更快。常见手段：

- 按内存布局顺序访问数组。
- 循环交换。
- 循环分块。
- 减少跨步访问。

C 的二维数组按行主序，内层循环访问连续列通常更好：

```c
for (i = 0; i < n; i++)
  for (j = 0; j < m; j++)
    sum += a[i][j];
```

## 典型题型

1. 判断指令之间的数据相关。
2. 给出一个合法的基本块调度。
3. 解释为什么某次代码移动不安全。
4. 判断数组访问是否具有良好局部性。

## 易错点

- 机器相关优化不能只看语句独立，还要看异常和内存别名。
- 指令重排必须保持单线程可观察行为。
- 缓存优化常和数组存储顺序有关。
