# 第 11 章 编译系统和运行时系统

## 学完要会什么

你要能把编译器放到完整工具链中理解，说明 C 编译系统各环节，也要了解 Java 虚拟机、即时编译和垃圾收集在运行时系统中的位置。

## C 语言编译系统

完整流程：

```text
源文件 .c
  -> 预处理器
  -> 编译器
  -> 汇编器
  -> 目标文件 .o/.obj
  -> 链接器
  -> 可执行文件
  -> 装入器
  -> 运行
```

预处理器处理：

- `#include`
- `#define`
- 条件编译

编译器生成汇编或中间目标代码。汇编器把汇编转成机器码形式的目标文件。链接器解析外部符号，把多个目标文件和库合成可执行文件。

## 目标文件

目标文件通常包含：

- 代码段。
- 数据段。
- 符号表。
- 重定位信息。
- 调试信息。

未解析的外部符号会留给链接器处理。

## 链接

静态链接在生成可执行文件时把库代码合入。动态链接在装入或运行时再解析共享库。

链接器要解决：

- 符号解析：名字到底对应哪个定义。
- 重定位：确定代码和数据的最终地址后修正引用。

## 装入

装入器把可执行文件映射到进程地址空间，设置栈、堆、动态库，跳转到入口点开始执行。

这连接了第 6 章的运行时内存组织。

## Java 运行时系统

Java 源程序通常先编译成字节码：

```text
.java -> .class -> JVM 执行
```

JVM 提供虚拟指令集、类加载、验证、安全检查、解释执行、即时编译和垃圾收集。

即时编译器会把热点字节码编译成本机代码，提高运行速度。

## 垃圾收集

垃圾收集自动回收不可达对象，减轻程序员管理内存负担。

基本概念：

- 根集合：栈、全局变量、寄存器中可直接引用的对象。
- 可达对象：从根集合沿引用能到达的对象。
- 垃圾：不可达对象。

常见算法：

- 标记清扫：标记可达对象，再清扫未标记对象。
- 复制收集：把可达对象复制到新空间。
- 分代收集：基于多数对象很快死亡的经验，把堆分代管理。

## 与作业的联系

作业中的 x86-64 汇编注释对应编译系统后半段：高级语言经编译、汇编、链接后成为可执行程序。函数参数寄存器、返回值寄存器、栈帧建立和恢复，都属于 ABI 与运行时约定。

理解这些内容有助于解释：

- 为什么函数返回值在 `eax/rax`。
- 为什么递归调用要保存返回地址。
- 为什么链接器需要符号表。
- 为什么目标文件不能直接当最终程序运行。

## 典型题型

1. 写出 C 程序从源文件到运行的流程。
2. 区分编译、汇编、链接、装入。
3. 解释静态链接和动态链接。
4. 说明目标文件中符号表和重定位信息的作用。
5. 解释 JVM、字节码和即时编译。
6. 说明垃圾收集的可达性思想。

## 易错点

- 编译器不负责把所有库函数代码都找齐，链接器负责符号解析和合并。
- 目标文件不是可执行文件，通常仍含未重定位地址和外部符号。
- JVM 执行字节码不等于只能解释执行，热点代码可即时编译。
- 垃圾收集回收的是不可达对象，不是“不再使用但仍可达”的对象。
