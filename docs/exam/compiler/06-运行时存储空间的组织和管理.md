# 第 6 章 运行时存储空间的组织和管理

## 学完要会什么

你要能解释程序运行时内存区域，理解活动记录、运行栈、作用域、参数传递、静态链和动态链，并能把函数调用和汇编栈帧联系起来。

## 运行时内存划分

典型运行时内存可分为：

```text
代码区：程序指令
静态区：全局变量、静态变量、常量
栈区：过程调用的活动记录
堆区：动态分配对象
```

局部变量通常在栈帧中，生命周期随调用开始和结束。`malloc/new` 分配的数据在堆上，需要运行时系统管理。

## 活动记录

一次过程调用对应一个活动记录，也叫栈帧。

常见内容：

- 返回地址。
- 动态链：指向调用者的活动记录。
- 静态链：指向词法外层过程的活动记录，用于访问非局部变量。
- 保存的寄存器。
- 形参。
- 局部变量。
- 临时变量。

不同机器和 ABI 的布局不同，但思想一致。

## 作用域和绑定

名字的作用域决定名字在程序文本中哪里可见。绑定指名字和实体之间的关联。

静态作用域按程序文本结构确定，编译期可分析。动态作用域按调用链确定，运行期才知道。

现代主流语言多用静态作用域。

## 静态链和动态链

动态链反映调用关系：谁调用我，我的动态链就指向谁。

静态链反映词法嵌套关系：我定义在哪个外层过程里，静态链就帮助我找到那个外层过程的活动记录。

访问非局部变量时，编译器可沿静态链走若干层，再按偏移找到变量。

## 参数传递

常见传参方式：

- 值调用：把实参值复制给形参，函数内修改不影响实参。
- 引用调用：形参是实参别名，修改形参影响实参。
- 换名调用：类似把实参表达式按名字代入，较少见。

C 语言是值调用。传指针时，指针本身仍按值传递，但可通过指针修改所指对象。

## 栈帧和 x86-64 作业联系

作业中的 Ackermann 函数汇编体现了典型栈帧：

```asm
push rbp
mov  rbp, rsp
sub  rsp, 16
...
leave
ret
```

在常见 x86-64 System V 调用约定中，前几个整型参数用寄存器传递，例如第 1、2 个整型参数常在 `edi`、`esi`。返回值放在 `eax` 或 `rax`。

编译器可能把寄存器参数保存到栈帧中的局部位置，例如 `[rbp-4]`、`[rbp-8]`，方便后续访问。

递归调用时，每次调用都有自己的活动记录，因此同名局部变量不会互相覆盖。

## 堆管理

堆用于动态分配大小或生命周期无法在编译期确定的数据。运行时系统要处理：

- 分配和释放。
- 空闲块管理。
- 碎片问题。
- 垃圾回收。

垃圾回收常见思路包括标记清扫、引用计数、复制收集、分代收集。教材中部分内容偏扩展，理解基本问题即可。

## 典型题型

1. 画过程调用时的运行栈。
2. 判断变量在静态区、栈区还是堆区。
3. 比较值调用和引用调用。
4. 解释递归为什么需要多个活动记录。
5. 根据嵌套过程说明静态链访问非局部变量。
6. 结合汇编说明参数和返回值位置。

## 易错点

- 动态链不是静态链。动态链看调用者，静态链看词法外层。
- C 的指针参数不是引用调用，仍然是值调用。
- 递归不需要复制代码，只需要新的活动记录。
- 返回局部变量地址是危险的，因为局部变量所在栈帧会失效。
