    第 5 章 类型检查¶

    学完要会什么¶

    你要能解释类型系统的作用，能写简单类型规则，能检查表达式和赋值语句类型，理解类型等价、类型转换、函数重载和多态的基本思想。

    类型系统为什么重要¶

    类型系统用于在编译期尽早发现错误，并指导代码生成。

    它能发现：

    • 把数组当函数调用。
    • 对整数取字段。
    • 给 int 变量赋字符串。
    • 函数实参与形参类型或个数不匹配。
    • 返回语句类型与函数声明不一致。

    类型还影响目标代码，例如整数加法和浮点加法通常对应不同机器指令。

    类型表达式¶

    类型可以用表达式递归描述。

    常见形式：

    基本类型：int, real, char, bool
数组：array(n, T)
指针：pointer(T)
函数：T1 x T2 x ... -> R
记录：record((name1:T1), (name2:T2), ...)

    C 声明题本质上是在还原类型表达式。

    例如：

    int* (*a[10])[10];

    可读作：a 是含 10 个元素的数组；每个元素是指针；该指针指向含 10 个元素的数组；数组元素是 int*。

    读 C 声明的技巧：从标识符出发，优先处理括号内结构，再按 []、()、* 的结合关系向外扩展。

    类型规则¶

    类型规则描述表达式类型如何推导。

    例如加法：

    E1.type = int, E2.type = int
--------------------------------
E1 + E2 的 type = int

    如果允许自动提升：

    int + real -> real
real + int -> real

    则编译器可能在中间代码中插入转换：

    t1 = int_to_real(i)
t2 = t1 + r

    类型检查和类型推导¶

    类型检查：已知或声明了类型，检查表达式是否符合规则。

    类型推导：根据使用方式推断类型。例如 x + 1 暗示 x 至少应是数值类型。

    多数课程题更偏类型检查。

    类型等价¶

    结构等价：两个类型结构相同就等价。

    名字等价：两个类型必须来自同一个类型名声明才等价。

    例子：

    typedef struct { int x; } A;
typedef struct { int x; } B;

    按结构等价，A 和 B 可视为同型；按名字等价，不同。

    类型转换¶

    类型转换分为隐式转换和显式转换。

    隐式转换由编译器自动插入，如 int 转 real。显式转换由程序员写出，如 (int)x。

    需要警惕：宽化转换通常安全，如 int -> real；窄化转换可能丢信息，如 real -> int。

    函数和算符重载¶

    重载指同一名字有多个类型签名。编译器根据实参类型选择匹配版本。

    例如 + 可表示整数加法、浮点加法、字符串连接。类型检查要解析出具体使用哪一个。

    多态¶

    多态允许同一段程序适用于多种类型。常见形式：

    • 参数多态：泛型函数，如 identity<T>(x:T):T。
    • 子类型多态：子类对象可在父类位置使用。
    • ad hoc 多态：重载。

    教材中带星号部分可作为扩展，考试通常更重视基本类型规则和声明解释。

    典型题型¶

    1. 给 C 声明，解释变量类型。
    2. 给表达式和符号表，判断类型是否正确。
    3. 写赋值、数组访问、函数调用的类型规则。
    4. 判断是否需要类型转换，写出插入的转换。
    5. 比较结构等价和名字等价。

    易错点¶

    • int c[20](int k); 在标准 C 中非法，因为数组元素不能是函数类型；合法形式应是 int (*c[20])(int k);。
    • 类型检查依赖符号表，没有声明信息就无从检查。
    • 类型转换不是优化，它属于语义处理或中间代码生成前后的语义保持工作。
    • 指针、数组、函数声明要尊重括号。

    自测清单¶

    • 能否解释 int* (*(*b)[10])[10];？
    • 能否判断 array(10, int) 与 array(20, int) 是否等价？
    • 能否说明何时插入 int_to_real？
    • 能否写出函数调用的类型检查条件？
