    编译原理速通笔记¶

    学习路线 词法分析 语法分析 考前总复习

    编译原理速通学习路线¶

    资料来源：本目录下《编译原理陈意云第3版.pdf》、lec/lec1.ppt 至 lec6.ppt、课程考核说明和已布置作业。未做外部检索。

    这门课到底学什么¶

    编译器做的事可以压成一句话：把源程序一步步变成目标机器能执行的代码，并在每一步保持程序含义不变。

    主线如下：

    字符流
  -> 词法分析：字符变 token
  -> 语法分析：token 变语法树或分析树
  -> 语义分析：检查类型、作用域、声明、控制约束
  -> 中间代码生成：语法树变中间表示
  -> 机器无关优化：改进中间表示
  -> 目标代码生成：中间表示变汇编或机器代码
  -> 机器相关优化：利用寄存器、流水线、局部性等机器特征

    符号表贯穿所有阶段：词法阶段建名字条目，语义阶段补类型和作用域，代码生成阶段查地址、偏移、链接信息。

    按教材章节的学习顺序¶

    40 学时课程建议重点掌握第 1 至第 9 章。第 11、12 章适合扩展到运行时系统和面向对象语言。第 10、13 章属于更深入主题，适合在主线学完后选读。

    建议顺序：

    1. 第 1 章：先建立编译阶段地图。
    2. 第 2 章：词法分析，掌握正规式、NFA、DFA、最小化。
    3. 第 3 章：语法分析，掌握文法、FIRST/FOLLOW、LL(1)、LR/SLR/LALR。
    4. 第 4 章：语法制导翻译，理解属性、翻译方案和语法树构造。
    5. 第 5 章：类型检查，理解类型系统和类型推导。
    6. 第 6 章：运行时存储，理解栈帧、作用域、参数传递。
    7. 第 7 章：中间代码，掌握三地址码、布尔表达式、数组地址、过程调用。
    8. 第 8 章：目标代码生成，掌握基本块、流图、寄存器分配的基本思想。
    9. 第 9 章：机器无关优化，掌握公共子表达式、复制传播、活跃变量、到达定值、循环优化。
    10. 第 11 章：编译系统和运行时系统，连接预处理、汇编、链接、装入和 Java 虚拟机。
    11. 第 10、12、13 章：作为扩展，分别看机器相关优化、面向对象语言、函数式语言。

    考核导向¶

    课程考核说明中：期末考试 40%，课程实践 30%，平时作业 20%，平时测验 10%。因此学习时要同时抓两类能力：

    • 纸笔能力：会算 token 流、FIRST/FOLLOW、LL(1) 表、LR 项目集、属性值、三地址码、数据流方程。
    • 实践能力：能把词法分析器、语法分析器、中间代码生成和简单解释执行串起来。

    作业已经出现过的题型包括：C 声明类型解释、词法记号流、x86-64 汇编和递归调用约定。这类题跨越第 1、2、6、7、8、11 章，建议反复练。

    每章怎么读¶

    每个章节速通文件都按同一结构写：

    • 学完要会什么：本章出口能力。
    • 核心概念：考试和实践都会用的定义。
    • 必会算法：需要能手算或实现的过程。
    • 典型题型：期末可能怎么问。
    • 易错点：最容易丢分的位置。
    • 自测清单：读完后立刻检查。

    不要把本课程当成背定义课。真正的主线是：每个阶段接收什么输入、输出什么结构、依赖什么表、可能报什么错、怎样保持语义不变。

    第 1 章 引论¶

    学完要会什么¶

    你要能画出编译器各阶段，解释每一阶段输入、输出和作用，并能用一个简单赋值语句说明 token、语法树、语义检查、中间代码、目标代码之间的关系。

    编译器的基本阶段¶

    编译器通常分为前端和后端。

    前端关心源语言，后端关心目标机器：

    前端：词法分析 -> 语法分析 -> 语义分析 -> 中间代码生成
后端：代码优化 -> 目标代码生成 -> 机器相关优化

    典型例子：

    position = initial + rate * 60

    词法分析把字符流切成 token：

    (id, position) (=) (id, initial) (+) (id, rate) (*) (num, 60)

    语法分析识别表达式结构，例如 rate * 60 优先于加法。语义分析检查 position、initial、rate 是否声明，类型是否能参与加法、乘法和赋值。中间代码可能生成：

    t1 = int_to_real(60)
t2 = rate * t1
t3 = initial + t2
position = t3

    优化阶段可能删除冗余转换、合并临时变量。代码生成阶段再把中间表示转成目标机器指令。

    符号表¶

    符号表保存名字的信息，是全程共享的数据结构。

    常见字段包括：

    • 名字：如 position。
    • 种类：变量、函数、类型名、字段、标签。
    • 类型：int、real、数组、函数类型等。
    • 作用域：全局、局部、嵌套块。
    • 地址信息：偏移量、静态区位置、栈帧位置、寄存器位置。

    词法分析器发现标识符后通常会查或插入符号表；语义分析补充类型和作用域；代码生成查询地址和偏移。

    编译器和解释器¶

    编译器先翻译再执行，解释器边读边执行。

    编译器优点是运行快、能做全局优化；解释器优点是交互性强、移植容易、调试方便。现代系统常混合二者，例如 Java 先编译成字节码，再由虚拟机解释或即时编译。

    编译系统不只包含编译器¶

    一个 C 程序从源文件到运行通常经历：

    预处理器 -> 编译器 -> 汇编器 -> 链接器 -> 装入器

    预处理器处理 #include、宏替换和条件编译。编译器生成汇编。汇编器生成目标文件。链接器合并目标文件和库，解析外部符号。装入器把可执行文件放入内存并启动。

    典型题型¶

    1. 给出语句，写词法记号流。
    2. 说明编译器各阶段的输入和输出。
    3. 判断某个错误在哪个阶段发现：拼错非法字符是词法错误；括号不匹配是语法错误；未声明变量或类型不匹配是语义错误。
    4. 解释编译器、解释器、汇编器、链接器、装入器的区别。

    易错点¶

    • token 不是字符，也不是字符串本身，而是“种别 + 属性值”的二元组。
    • 语法正确不代表语义正确，例如 int x; x[3] = 1; 语法可能能过，但类型检查会失败。
    • 优化必须保持语义等价，不能只看指令更少。
    • 符号表不是某一阶段独有，而是多阶段共享。

    自测清单¶

    • 能否从字符流一路说到目标代码？
    • 能否解释为什么乘法优先级属于语法分析问题？
    • 能否说明未声明变量为什么不是词法错误？
    • 能否解释 C 程序为什么还需要链接？

    第 2 章 词法分析¶

    学完要会什么¶

    你要能把源程序切成 token，能用正规式描述 token 模式，能把正规式转换为 NFA，再转换为 DFA，并能对 DFA 做化简。

    词法记号、模式、词法单元¶

    三个概念要分清：

    • 词法记号 token：语法分析器看到的类别，如 id、num、if、+。
    • 模式 pattern：描述某类 token 的规则，如标识符是“字母开头，后接字母或数字”。
    • 词法单元 lexeme：源程序中实际出现的字符串，如 count、123。

    词法分析器通常输出：

    (token_name, attribute_value)

    例如 int* (*(*b)[10])[10]; 的记号流可写成：

    int  *  (  *  (  *  id:b  )  [  num:10  ]  )  [  num:10  ]  ;

    正规式¶

    正规式用于描述正规语言。常用运算：

    • 并：r|s，表示属于 r 或 s。
    • 连接：rs，表示先匹配 r 再匹配 s。
    • 闭包：r*，表示重复 0 次或多次。
    • 正闭包：r+，表示重复 1 次或多次。
    • 可选：r?，表示 0 次或 1 次。

    常见 token 正规式：

    letter = A|...|Z|a|...|z
digit  = 0|1|...|9
id     = letter (letter|digit)*
num    = digit+ (. digit+)? (E (+|-)? digit+)?

    有限自动机¶

    NFA 和 DFA 都识别正规语言。

    DFA 特征：每个状态遇到每个输入符号最多只有一条确定转移，没有 epsilon 转移。

    NFA 特征：同一状态遇到同一输入可以有多条转移，也可以有 epsilon 转移。

    NFA 更容易从正规式构造，DFA 更适合实现词法分析器。

    NFA 到 DFA：子集构造法¶

    核心思想：DFA 的一个状态对应 NFA 的一组状态。

    步骤：

    1. 从 epsilon-closure(start) 得到 DFA 初态。
    2. 对每个 DFA 状态集合 T 和输入符号 a，计算 epsilon-closure(move(T, a))。
    3. 如果得到的新集合没出现过，就作为新 DFA 状态加入。
    4. 包含 NFA 终态的 DFA 状态就是 DFA 终态。

    记住两个函数：

    move(T, a)：从 T 中任一状态读 a 能到达的状态集合
epsilon-closure(T)：从 T 出发只走 epsilon 边能到达的状态集合，含 T 本身

    DFA 化简¶

    目标：合并等价状态。两个状态等价，意思是从它们出发对任何后续输入，要么都接受，要么都拒绝。

    常用分割法：

    1. 初始划分为终态集合和非终态集合。
    2. 对每个分组，检查其成员在同一输入下是否转向同一分组。
    3. 若不同，继续细分。
    4. 直到不能再细分。

    词法分析器生成器¶

    Lex/Flex 类工具通常接收“正规式 + 动作代码”，生成扫描器。扫描器用最长匹配原则选择词法单元；若多个规则匹配同样长的串，通常选择先出现的规则。

    例如关键字和标识符冲突时：

    if      return IF;
[A-Za-z][A-Za-z0-9]* return ID;

    因为 if 规则写在前面，所以 if 被识别为关键字，不是普通标识符。

    典型题型¶

    1. 写某段 C 代码或声明的 token 流。
    2. 为标识符、数字、注释、邮箱等写正规式。
    3. 由正规式画 NFA。
    4. 由 NFA 构造 DFA。
    5. 对 DFA 做最小化。
    6. 判断词法错误，例如非法字符、未闭合字符串。

    易错点¶

    • 关键字通常可先按标识符识别，再查关键字表，也可以规则优先处理。
    • * 在正规式中表示闭包，在 C 声明里是指针，在词法中只是一个运算符或界符，语境不同。
    • 最长匹配优先于规则先后。规则先后只在同样长时起作用。
    • epsilon-closure 一定包含原状态本身。

    自测清单¶

    • 能否写出 int* (*(*b)[10])[10]; 的 token 流？
    • 能否把 letter(letter|digit)* 转成自动机？
    • 能否解释 NFA 与 DFA 的区别？
    • 能否手算一个小 NFA 的子集构造表？

    第 3 章 语法分析¶

    学完要会什么¶

    你要能读写上下文无关文法，判断推导、分析树、二义性，能做 LL(1) 预测分析，也能理解 LR/SLR/LALR 分析表的构造思想。

    上下文无关文法¶

    文法通常写成四元组：

    G = (Vn, Vt, P, S)
    • Vn：非终结符集合，如 Expr、Stmt。
    • Vt：终结符集合，即 token。
    • P：产生式集合。
    • S：开始符号。

    例子：

    E -> E + T | T
T -> T * F | F
F -> ( E ) | id

    该文法表达了乘法优先于加法，但有左递归，不适合直接做递归下降。

    推导、句型、句子、语言¶

    从开始符号反复应用产生式得到的串叫句型；只含终结符的句型叫句子；某文法能生成的全部句子构成该文法的语言。

    最左推导每次替换最左非终结符；最右推导每次替换最右非终结符。自顶向下分析通常模拟最左推导，自底向上分析通常反向模拟最右推导。

    二义性¶

    如果一个句子有两棵不同分析树，或有两个不同最左推导，则文法二义。

    典型二义性：

    E -> E + E | E * E | (E) | id

    id + id * id 可按先加或先乘解释。解决方法是重写文法，让优先级和结合性体现在文法结构中。

    悬空 else 也是经典二义性：

    if E then if E then S else S

    通常规定 else 归属于最近的未匹配 if。

    消除左递归¶

    直接左递归：

    A -> A alpha | beta

    可改写为：

    A  -> beta A'
A' -> alpha A' | epsilon

    例如：

    E -> E + T | T

    改为：

    E  -> T E'
E' -> + T E' | epsilon

    提左因子¶

    若多个候选式有共同前缀：

    A -> alpha beta1 | alpha beta2

    改为：

    A  -> alpha A'
A' -> beta1 | beta2

    这是为了让自顶向下分析器看较少的输入符号就能决定用哪个产生式。

    FIRST 和 FOLLOW¶

    FIRST(alpha)：从 alpha 能推出的串的第一个终结符集合；若 alpha 能推出空串，则包含 epsilon。

    FOLLOW(A)：在某个句型中可以紧跟在非终结符 A 后面的终结符集合。若 A 可在句尾，FOLLOW(A) 包含输入结束符 $。

    构造 LL(1) 分析表时：

    • 对产生式 A -> alpha，把它填入 M[A, a]，其中 a 属于 FIRST(alpha) 且 a != epsilon。
    • 如果 epsilon 属于 FIRST(alpha)，则对每个 b 属于 FOLLOW(A)，把 A -> alpha 填入 M[A, b]。
    • 一个表格项有多个产生式就是冲突，该文法不是 LL(1)。

    递归下降和预测分析¶

    递归下降为每个非终结符写一个过程。预测分析是非递归版本，用栈和分析表驱动。

    预测分析基本过程：

    1. 栈初始为 $ S，输入末尾加 $。
    2. 栈顶是终结符时，必须和当前输入匹配。
    3. 栈顶是非终结符 A 时，用当前输入 token 查 M[A, token]。
    4. 找到产生式后弹出 A，把右部逆序压栈。

    LR 分析¶

    LR 分析从左到右扫描输入，构造最右推导的逆过程。动作包括移进、归约、接受、报错。

    LR 项目形如：

    A -> alpha . beta

    点表示已经识别到的位置。

    核心函数：

    • closure(I)：如果项目中点后是非终结符 B，则加入 B 的所有产生式初始项目。
    • goto(I, X)：从项目集 I 中所有点后为 X 的项目出发，把点越过 X，再取 closure。

    SLR 使用 LR(0) 项目集和 FOLLOW 集决定归约。LR(1) 项目带展望符，能力更强。LALR 合并 LR(1) 中核心相同的项目集，表更小，工具中常用。

    典型题型¶

    1. 判断某串是否属于某文法。
    2. 画分析树，写最左推导或最右推导。
    3. 判断文法是否二义。
    4. 消除左递归、提左因子。
    5. 计算 FIRST/FOLLOW。
    6. 构造 LL(1) 预测分析表。
    7. 构造 LR(0)/SLR 项目集和分析表，判断冲突。

    易错点¶

    • FIRST(A) 和 FOLLOW(A) 不要混。FIRST 看“开头能是什么”，FOLLOW 看“后面能跟什么”。
    • epsilon 不会进入 FOLLOW 集。
    • 消除左递归可能改变分析树形态，但不能改变语言。
    • LR 项目集构造时，closure 只对点后是非终结符的项目扩展。
    • SLR 归约看 FOLLOW，LR(1) 归约看项目自带展望符。

    自测清单¶

    • 能否把表达式文法改写成 LL(1) 风格？
    • 能否手算 FIRST/FOLLOW？
    • 能否解释 LL 和 LR 的方向差异？
    • 能否看分析表判断移进/归约冲突？

    第 4 章 语法制导的翻译¶

    学完要会什么¶

    你要能给文法符号附加属性，写语义规则，理解 S 属性定义、L 属性定义，能在语法分析过程中构造语法树或生成中间代码。

    语法制导定义¶

    语法制导定义由文法产生式和语义规则组成。每个文法符号可以带属性，语义规则说明这些属性如何计算。

    属性分两类：

    • 综合属性：由子节点或自身信息计算，信息自下而上传递。
    • 继承属性：由父节点或兄弟节点传入，信息自上而下或横向传递。

    例子：

    E -> E1 + T
E.val = E1.val + T.val

    这里 E.val 是综合属性。

    属性依赖图和计算次序¶

    属性之间存在依赖关系。若 b 的计算依赖 c，则依赖图中有边 c -> b。属性计算顺序必须是依赖图的拓扑序。

    如果依赖图有环，则属性无法按正常方式求值。

    S 属性定义¶

    只含综合属性的语法制导定义叫 S 属性定义。

    它适合自底向上分析，因为归约一个产生式时，右部符号的属性已经算好，可以直接计算左部属性。

    例子：

    L -> E \n     print(E.val)
E -> E1 + T  E.val = E1.val + T.val
E -> T       E.val = T.val
T -> num     T.val = num.lexval

    L 属性定义¶

    L 属性定义允许继承属性，但有约束：产生式 A -> X1 X2 ... Xn 中，Xi 的继承属性只能依赖：

    • A 的继承属性。
    • Xi 左边符号 X1 ... Xi-1 的属性。

    这保证自顶向下或深度优先遍历时能计算。

    翻译方案¶

    翻译方案把语义动作嵌入产生式右部。动作出现的位置决定执行时机。

    例如构造后缀式：

    E -> E1 + T { print('+') }
E -> T
T -> num { print(num.lexval) }

    输入 3 + 4 输出 3 4 +。

    构造语法树¶

    抽象语法树会省略不影响语义的语法细节，如括号、分号、某些中间非终结符。

    表达式：

    a + b * c

    抽象语法树可理解为：

        +
   / \
  a   *
     / \
    b   c

    乘法成为加法右子树，体现优先级。

    典型应用¶

    语法制导翻译可用于：

    • 计算表达式值。
    • 构造抽象语法树。
    • 生成三地址码。
    • 填写类型信息。
    • 回填跳转地址。
    • 管理符号表作用域。

    典型题型¶

    1. 给定语法制导定义，计算某输入串的属性值。
    2. 判断某属性定义是否为 S 属性或 L 属性。
    3. 画属性依赖图，给出计算顺序。
    4. 在产生式中嵌入动作，生成后缀式或三地址码。
    5. 给表达式构造语法树。

    易错点¶

    • 继承属性不是“只能从父亲来”，也可以从左兄弟来。
    • S 属性定义一定是 L 属性定义的特例。
    • 翻译方案中动作位置很重要，放在右部不同位置会改变执行时机。
    • 语法树不等于抽象语法树。抽象语法树更接近语义结构。

    自测清单¶

    • 能否说明综合属性和继承属性的方向？
    • 能否判断一个属性定义是否能在一次深度优先遍历中计算？
    • 能否为表达式生成后缀式？
    • 能否用语义动作构造 AST 节点？

    第 5 章 类型检查¶

    学完要会什么¶

    你要能解释类型系统的作用，能写简单类型规则，能检查表达式和赋值语句类型，理解类型等价、类型转换、函数重载和多态的基本思想。

    类型系统为什么重要¶

    类型系统用于在编译期尽早发现错误，并指导代码生成。

    它能发现：

    • 把数组当函数调用。
    • 对整数取字段。
    • 给 int 变量赋字符串。
    • 函数实参与形参类型或个数不匹配。
    • 返回语句类型与函数声明不一致。

    类型还影响目标代码，例如整数加法和浮点加法通常对应不同机器指令。

    类型表达式¶

    类型可以用表达式递归描述。

    常见形式：

    基本类型：int, real, char, bool
数组：array(n, T)
指针：pointer(T)
函数：T1 x T2 x ... -> R
记录：record((name1:T1), (name2:T2), ...)

    C 声明题本质上是在还原类型表达式。

    例如：

    int* (*a[10])[10];

    可读作：a 是含 10 个元素的数组；每个元素是指针；该指针指向含 10 个元素的数组；数组元素是 int*。

    读 C 声明的技巧：从标识符出发，优先处理括号内结构，再按 []、()、* 的结合关系向外扩展。

    类型规则¶

    类型规则描述表达式类型如何推导。

    例如加法：

    E1.type = int, E2.type = int
--------------------------------
E1 + E2 的 type = int

    如果允许自动提升：

    int + real -> real
real + int -> real

    则编译器可能在中间代码中插入转换：

    t1 = int_to_real(i)
t2 = t1 + r

    类型检查和类型推导¶

    类型检查：已知或声明了类型，检查表达式是否符合规则。

    类型推导：根据使用方式推断类型。例如 x + 1 暗示 x 至少应是数值类型。

    多数课程题更偏类型检查。

    类型等价¶

    结构等价：两个类型结构相同就等价。

    名字等价：两个类型必须来自同一个类型名声明才等价。

    例子：

    typedef struct { int x; } A;
typedef struct { int x; } B;

    按结构等价，A 和 B 可视为同型；按名字等价，不同。

    类型转换¶

    类型转换分为隐式转换和显式转换。

    隐式转换由编译器自动插入，如 int 转 real。显式转换由程序员写出，如 (int)x。

    需要警惕：宽化转换通常安全，如 int -> real；窄化转换可能丢信息，如 real -> int。

    函数和算符重载¶

    重载指同一名字有多个类型签名。编译器根据实参类型选择匹配版本。

    例如 + 可表示整数加法、浮点加法、字符串连接。类型检查要解析出具体使用哪一个。

    多态¶

    多态允许同一段程序适用于多种类型。常见形式：

    • 参数多态：泛型函数，如 identity<T>(x:T):T。
    • 子类型多态：子类对象可在父类位置使用。
    • ad hoc 多态：重载。

    教材中带星号部分可作为扩展，考试通常更重视基本类型规则和声明解释。

    典型题型¶

    1. 给 C 声明，解释变量类型。
    2. 给表达式和符号表，判断类型是否正确。
    3. 写赋值、数组访问、函数调用的类型规则。
    4. 判断是否需要类型转换，写出插入的转换。
    5. 比较结构等价和名字等价。

    易错点¶

    • int c[20](int k); 在标准 C 中非法，因为数组元素不能是函数类型；合法形式应是 int (*c[20])(int k);。
    • 类型检查依赖符号表，没有声明信息就无从检查。
    • 类型转换不是优化，它属于语义处理或中间代码生成前后的语义保持工作。
    • 指针、数组、函数声明要尊重括号。

    自测清单¶

    • 能否解释 int* (*(*b)[10])[10];？
    • 能否判断 array(10, int) 与 array(20, int) 是否等价？
    • 能否说明何时插入 int_to_real？
    • 能否写出函数调用的类型检查条件？

    第 6 章 运行时存储空间的组织和管理¶

    学完要会什么¶

    你要能解释程序运行时内存区域，理解活动记录、运行栈、作用域、参数传递、静态链和动态链，并能把函数调用和汇编栈帧联系起来。

    运行时内存划分¶

    典型运行时内存可分为：

    代码区：程序指令
静态区：全局变量、静态变量、常量
栈区：过程调用的活动记录
堆区：动态分配对象

    局部变量通常在栈帧中，生命周期随调用开始和结束。malloc/new 分配的数据在堆上，需要运行时系统管理。

    活动记录¶

    一次过程调用对应一个活动记录，也叫栈帧。

    常见内容：

    • 返回地址。
    • 动态链：指向调用者的活动记录。
    • 静态链：指向词法外层过程的活动记录，用于访问非局部变量。
    • 保存的寄存器。
    • 形参。
    • 局部变量。
    • 临时变量。

    不同机器和 ABI 的布局不同，但思想一致。

    作用域和绑定¶

    名字的作用域决定名字在程序文本中哪里可见。绑定指名字和实体之间的关联。

    静态作用域按程序文本结构确定，编译期可分析。动态作用域按调用链确定，运行期才知道。

    现代主流语言多用静态作用域。

    静态链和动态链¶

    动态链反映调用关系：谁调用我，我的动态链就指向谁。

    静态链反映词法嵌套关系：我定义在哪个外层过程里，静态链就帮助我找到那个外层过程的活动记录。

    访问非局部变量时，编译器可沿静态链走若干层，再按偏移找到变量。

    参数传递¶

    常见传参方式：

    • 值调用：把实参值复制给形参，函数内修改不影响实参。
    • 引用调用：形参是实参别名，修改形参影响实参。
    • 换名调用：类似把实参表达式按名字代入，较少见。

    C 语言是值调用。传指针时，指针本身仍按值传递，但可通过指针修改所指对象。

    栈帧和 x86-64 作业联系¶

    作业中的 Ackermann 函数汇编体现了典型栈帧：

    push rbp
mov  rbp, rsp
sub  rsp, 16
...
leave
ret

    在常见 x86-64 System V 调用约定中，前几个整型参数用寄存器传递，例如第 1、2 个整型参数常在 edi、esi。返回值放在 eax 或 rax。

    编译器可能把寄存器参数保存到栈帧中的局部位置，例如 [rbp-4]、[rbp-8]，方便后续访问。

    递归调用时，每次调用都有自己的活动记录，因此同名局部变量不会互相覆盖。

    堆管理¶

    堆用于动态分配大小或生命周期无法在编译期确定的数据。运行时系统要处理：

    • 分配和释放。
    • 空闲块管理。
    • 碎片问题。
    • 垃圾回收。

    垃圾回收常见思路包括标记清扫、引用计数、复制收集、分代收集。教材中部分内容偏扩展，理解基本问题即可。

    典型题型¶

    1. 画过程调用时的运行栈。
    2. 判断变量在静态区、栈区还是堆区。
    3. 比较值调用和引用调用。
    4. 解释递归为什么需要多个活动记录。
    5. 根据嵌套过程说明静态链访问非局部变量。
    6. 结合汇编说明参数和返回值位置。

    易错点¶

    • 动态链不是静态链。动态链看调用者，静态链看词法外层。
    • C 的指针参数不是引用调用，仍然是值调用。
    • 递归不需要复制代码，只需要新的活动记录。
    • 返回局部变量地址是危险的，因为局部变量所在栈帧会失效。

    自测清单¶

    • 能否画出 main -> f -> g 的栈帧链？
    • 能否解释递归调用的返回地址如何保存？
    • 能否说明为什么局部数组可能占用栈空间？
    • 能否解释 eax 中返回值和活动记录的关系？

    第 7 章 中间代码生成¶

    学完要会什么¶

    你要能把声明、赋值、数组访问、布尔表达式、控制流和过程调用翻译成中间表示，尤其是三地址代码。

    中间语言的作用¶

    中间表示连接前端和后端。它应当比源语言简单，又不绑定某台机器。

    常见中间表示：

    • 后缀表示：适合表达式求值。
    • 图形表示：语法树、DAG。
    • 三地址代码：最常考，也最便于优化和代码生成。
    • 静态单赋值形式 SSA：进阶优化常用。

    三地址代码¶

    三地址代码每条语句最多包含三个地址：两个源操作数和一个结果。

    常见形式：

    x = y op z
x = op y
x = y
if x relop y goto L
goto L
param x
call p, n
return x

    表达式：

    a = b * -c + b * -c

    可翻译为：

    t1 = -c
t2 = b * t1
t3 = -c
t4 = b * t3
t5 = t2 + t4
a = t5

    后续优化可发现公共子表达式。

    声明语句翻译¶

    声明的主要任务是填符号表，计算类型宽度和地址偏移。

    例如：

    int a;
float b;
int c[10];

    符号表可记录：

    a: type=int, offset=0
b: type=float, offset=4
c: type=array(10,int), offset=8

    偏移用于后续代码生成。

    数组地址计算¶

    一维数组 A[i] 地址：

    base(A) + i * width

    二维数组按行主序：

    A[i][j] = base(A) + ((i * n) + j) * width

    其中 n 是第二维长度。

    三地址代码例子：

    t1 = i * n
t2 = t1 + j
t3 = t2 * width
x = A[t3]

    教材和考试常考“数组元素地址计算的翻译方案”。

    布尔表达式翻译¶

    布尔表达式可翻译成数值，也可直接翻译成控制流。

    短路求值很重要：

    if (a < b && c < d) S1 else S2

    翻译思路：

    if a < b goto L1
goto Lfalse
L1:
if c < d goto Ltrue
goto Lfalse
Ltrue:
S1
goto Lnext
Lfalse:
S2
Lnext:

    && 中左边为假时不求右边；|| 中左边为真时不求右边。

    控制流语句¶

    if、while、for、switch 都可归结为条件跳转和标签。

    while (B) S：

    Lbegin:
  code(B, true=Lbody, false=Lnext)
Lbody:
  code(S)
  goto Lbegin
Lnext:

    回填¶

    生成跳转代码时，目标标签可能还不知道。回填技术先留下空位，等目标确定后统一填入。

    常见属性：

    • truelist：条件为真时待回填的跳转链。
    • falselist：条件为假时待回填的跳转链。
    • nextlist：语句执行完后待回填的跳转链。

    常用操作：

    makelist(i)
merge(p1, p2)
backpatch(p, target)

    过程调用¶

    调用通常翻译为：

    param a1
param a2
t = call f, 2

    编译器还要结合运行时存储布局处理实参求值、参数传递、返回值和调用约定。

    典型题型¶

    1. 表达式翻译成三地址码。
    2. 数组元素访问翻译成地址计算。
    3. if/while 翻译成带标签三地址码。
    4. 布尔表达式短路翻译。
    5. 使用回填技术列出 truelist/falselist/nextlist。
    6. 过程调用翻译。

    易错点¶

    • 数组地址计算要乘元素宽度。
    • 多维数组要明确行主序还是列主序，C 是行主序。
    • 布尔表达式不要默认求出 0/1，控制流翻译更常见。
    • 回填列表保存的是“尚未知道目标的跳转语句编号”。

    自测清单¶

    • 能否把 x = a[i] + b[j] 翻译为三地址码？
    • 能否写出 while 的标签结构？
    • 能否解释 && 的短路翻译？
    • 能否说明过程调用为什么依赖第 6 章的运行时组织？

    第 8 章 代码生成¶

    学完要会什么¶

    你要能理解目标代码生成器的输入输出，能划分基本块、构造流图，能用简单算法从三地址码生成目标代码，并理解寄存器分配的核心矛盾。

    代码生成器面对的问题¶

    目标代码生成不仅是“翻译指令”，还要处理：

    • 指令选择：用哪些目标机指令实现中间操作。
    • 寄存器分配：哪些值放寄存器，哪些值放内存。
    • 计算次序：先算哪个子表达式更省寄存器。
    • 地址计算：变量、数组、临时变量的地址。
    • 调用约定：参数、返回值、保存寄存器。

    目标语言和指令代价¶

    简单目标机可抽象为：

    LD  R, x      R = x
ST  x, R      x = R
ADD R, x      R = R + x
SUB R, x
MUL R, x

    指令代价可用指令数、访存次数、周期数估计。真实机器上访存通常比寄存器操作贵。

    基本块¶

    基本块是一段顺序执行的代码，只有入口第一条和出口最后一条。

    划分方法：

    1. 第一条语句是入口。
    2. 任意跳转目标是入口。
    3. 任意跳转语句的下一条是入口。
    4. 每个入口到下一个入口之前构成一个基本块。

    流图¶

    流图节点是基本块，边表示控制流可能从一个基本块转到另一个基本块。

    若基本块 B1 末尾是 goto B2，则有边 B1 -> B2。若条件跳转失败后继续执行下一块，也有一条落空边。

    流图是后续数据流分析和优化的基础。

    下次引用信息¶

    生成局部代码时，要知道变量之后是否还会被用到，以及下一次使用在哪里。

    如果某个变量当前值已经在寄存器中，且之后不再使用，就可以覆盖该寄存器。若变量之后还要用，覆盖前要确保它的值已保存。

    简单代码生成算法¶

    对三地址语句：

    x = y op z

    基本思路：

    1. 为 y 选择一个寄存器，必要时从内存装入。
    2. 对该寄存器执行 op z。
    3. 让寄存器保存 x 的值。
    4. 更新地址描述符和寄存器描述符。

    地址描述符记录某变量当前值在哪些位置；寄存器描述符记录某寄存器当前装了哪些变量。

    寄存器分配¶

    寄存器是稀缺资源。寄存器分配要决定哪些值常驻寄存器，哪些值溢出到内存。

    常见思想：

    • 局部寄存器分配：在基本块内部用下次引用信息。
    • 全局寄存器分配：跨基本块考虑活跃范围，常用图着色思想。

    如果同时活跃的变量太多，就需要溢出。溢出会增加加载和存储。

    条件语句代码生成¶

    三地址码：

    if x < y goto L1
goto L2

    可生成：

    CMP x, y
JL  L1
JMP L2

    真实机器中还要考虑条件码寄存器、分支预测、延迟槽等机器特性，属于更后面的优化内容。

    典型题型¶

    1. 给三地址码划分基本块。
    2. 构造流图。
    3. 根据简单目标机指令生成目标代码。
    4. 根据下次引用信息选择寄存器。
    5. 解释地址描述符和寄存器描述符。

    易错点¶

    • 基本块不能有中间入口，也不能有中间跳出。
    • 条件跳转后通常有两条出边：真分支和假分支。
    • 变量在寄存器中不代表内存中一定是最新值。
    • 代码生成依赖中间代码、符号表和运行时布局，不能孤立看。

    自测清单¶

    • 能否给一组三地址码标出 leader？
    • 能否画控制流图？
    • 能否解释为什么寄存器分配很难？
    • 能否从 x = y + z 生成简单装入、加法、存储指令？

    第 9 章 独立于机器的优化¶

    学完要会什么¶

    你要能识别常见优化机会，理解数据流分析的基本框架，能写到达定值、活跃变量等数据流方程，并能说明循环优化为什么重要。

    优化的原则¶

    优化必须保持程序语义。优化目标可能是：

    • 减少执行时间。
    • 减少代码大小。
    • 减少访存。
    • 减少能耗。

    本章“独立于机器”指优化主要发生在中间代码层，不依赖具体指令集。

    常见局部优化¶

    基本块内可做：

    • 公共子表达式删除。
    • 复制传播。
    • 常量折叠。
    • 常量传播。
    • 死代码删除。
    • 强度削弱。

    例子：

    t1 = a + b
t2 = a + b
x = t2

    若 a、b 中间未改变，则 t2 可替换为 t1。

    复制传播：

    x = y
z = x + 1

    可改为：

    z = y + 1

    若 x 后续不再使用，x = y 可进一步删除。

    DAG 优化¶

    基本块可构造成 DAG：叶子是变量或常量，内部节点是运算。相同运算和相同操作数组合可共享节点，用于发现公共子表达式。

    DAG 还能帮助删除无用赋值：如果某节点结果不会影响基本块出口活跃变量，就可以删除。

    数据流分析框架¶

    数据流分析在流图上求解信息集合。

    通用形式：

    OUT[B] = f_B(IN[B])
IN[B]  = 合并所有前驱的 OUT

    或反向问题：

    IN[B]  = f_B(OUT[B])
OUT[B] = 合并所有后继的 IN

    关键要素：

    • 方向：正向或反向。
    • 合并运算：并集或交集。
    • 传递函数：通常由 gen 和 kill 表示。
    • 初值和迭代顺序。

    到达定值¶

    一个定值 d: x = ... 到达某点，表示存在一条路径从 d 到该点，且路径上没有重新给 x 定值。

    它是正向、may 问题，合并用并集。

    方程：

    IN[B]  = union OUT[P]，P 是 B 的前驱
OUT[B] = gen[B] union (IN[B] - kill[B])

    应用：常量传播、复制传播、未初始化检查。

    活跃变量¶

    变量在某点活跃，表示从该点出发存在路径会使用它当前值，且在使用前没有重新定值。

    它是反向、may 问题，合并用并集。

    方程：

    OUT[B] = union IN[S]，S 是 B 的后继
IN[B]  = use[B] union (OUT[B] - def[B])

    应用：死代码删除、寄存器分配。

    可用表达式¶

    表达式在某点可用，表示从入口到该点的每条路径都已计算过该表达式，并且操作数没有被改写。

    它是正向、must 问题，合并用交集。

    应用：公共子表达式删除。

    循环优化¶

    循环执行次数多，是优化重点。

    常见循环优化：

    • 循环不变代码外提。
    • 归纳变量识别。
    • 强度削弱，如乘法变加法。
    • 删除冗余归纳变量。

    自然循环通常由回边形成。识别循环前要先理解支配关系：若所有从入口到 n 的路径都经过 d，则 d 支配 n。

    典型题型¶

    1. 对基本块做 DAG 优化。
    2. 找公共子表达式、复制传播、死代码。
    3. 给流图写到达定值方程并迭代求解。
    4. 给流图写活跃变量方程。
    5. 识别循环不变代码和归纳变量。

    易错点¶

    • may 问题通常用并集，must 问题通常用交集。
    • 到达定值是正向，活跃变量是反向。
    • 死代码删除不能删除有副作用的语句，例如函数调用、I/O、可能抛异常的操作。
    • 公共子表达式成立的前提是操作数中间未被改变。

    自测清单¶

    • 能否写出到达定值方程？
    • 能否写出活跃变量方程？
    • 能否区分 gen/kill 与 use/def？
    • 能否解释为什么循环优化收益大？

    第 10 章 依赖于机器的优化¶

    学习定位¶

    本章在教材中属于加星号的进阶内容。主线课程若时间有限，可只掌握基本概念：机器相关优化会利用具体处理器结构、寄存器、流水线、缓存和并行性。

    处理器体系结构相关因素¶

    机器相关优化关注：

    • 指令流水线。
    • 分支延迟和分支预测。
    • 多指令发射。
    • 寄存器数量和类别。
    • 缓存局部性。
    • 数据相关和控制相关。

    机器无关优化让中间代码更好；机器相关优化让目标代码更贴合硬件。

    代码调度¶

    代码调度通过调整指令顺序减少流水线停顿。

    例如：

    LD  R1, a
ADD R2, R1, R3

    如果加载后立刻使用 R1 会产生等待，可在中间插入与 R1 无关的指令。

    调度必须保持依赖关系：

    • 数据相关：后一条指令使用前一条结果。
    • 控制相关：指令是否执行依赖分支。
    • 资源相关：同一硬件资源不能同时使用。

    基本块调度¶

    基本块内部没有分支，适合做局部调度。调度常先构造数据依赖图，节点是指令，边表示必须先后执行。

    合法调度是依赖图的拓扑序。好的调度还要减少停顿和资源冲突。

    全局代码调度¶

    全局调度跨基本块移动代码，收益更高，风险也更高。移动指令时必须保证不会改变异常、内存访问、副作用和控制流语义。

    例如把循环中的不变计算移到循环前，是机器无关优化；但把某条加载提前到分支前，可能引入原本不会发生的异常，需要谨慎。

    软件流水¶

    软件流水用于循环，把不同迭代的指令交错执行，提高流水线利用率。

    直觉：

    第 i 次迭代做加载
第 i-1 次迭代做计算
第 i-2 次迭代做存储

    它需要处理循环启动、稳定阶段和收尾阶段。

    数据局部性优化¶

    缓存友好代码通常更快。常见手段：

    • 按内存布局顺序访问数组。
    • 循环交换。
    • 循环分块。
    • 减少跨步访问。

    C 的二维数组按行主序，内层循环访问连续列通常更好：

    for (i = 0; i < n; i++)
  for (j = 0; j < m; j++)
    sum += a[i][j];

    典型题型¶

    1. 判断指令之间的数据相关。
    2. 给出一个合法的基本块调度。
    3. 解释为什么某次代码移动不安全。
    4. 判断数组访问是否具有良好局部性。

    易错点¶

    • 机器相关优化不能只看语句独立，还要看异常和内存别名。
    • 指令重排必须保持单线程可观察行为。
    • 缓存优化常和数组存储顺序有关。

    自测清单¶

    • 能否区分机器无关优化和机器相关优化？
    • 能否看出 load-use 延迟？
    • 能否解释循环分块为什么提高缓存命中？

    第 11 章 编译系统和运行时系统¶

    学完要会什么¶

    你要能把编译器放到完整工具链中理解，说明 C 编译系统各环节，也要了解 Java 虚拟机、即时编译和垃圾收集在运行时系统中的位置。

    C 语言编译系统¶

    完整流程：

    源文件 .c
  -> 预处理器
  -> 编译器
  -> 汇编器
  -> 目标文件 .o/.obj
  -> 链接器
  -> 可执行文件
  -> 装入器
  -> 运行

    预处理器处理：

    • #include
    • #define
    • 条件编译

    编译器生成汇编或中间目标代码。汇编器把汇编转成机器码形式的目标文件。链接器解析外部符号，把多个目标文件和库合成可执行文件。

    目标文件¶

    目标文件通常包含：

    • 代码段。
    • 数据段。
    • 符号表。
    • 重定位信息。
    • 调试信息。

    未解析的外部符号会留给链接器处理。

    链接¶

    静态链接在生成可执行文件时把库代码合入。动态链接在装入或运行时再解析共享库。

    链接器要解决：

    • 符号解析：名字到底对应哪个定义。
    • 重定位：确定代码和数据的最终地址后修正引用。

    装入¶

    装入器把可执行文件映射到进程地址空间，设置栈、堆、动态库，跳转到入口点开始执行。

    这连接了第 6 章的运行时内存组织。

    Java 运行时系统¶

    Java 源程序通常先编译成字节码：

    .java -> .class -> JVM 执行

    JVM 提供虚拟指令集、类加载、验证、安全检查、解释执行、即时编译和垃圾收集。

    即时编译器会把热点字节码编译成本机代码，提高运行速度。

    垃圾收集¶

    垃圾收集自动回收不可达对象，减轻程序员管理内存负担。

    基本概念：

    • 根集合：栈、全局变量、寄存器中可直接引用的对象。
    • 可达对象：从根集合沿引用能到达的对象。
    • 垃圾：不可达对象。

    常见算法：

    • 标记清扫：标记可达对象，再清扫未标记对象。
    • 复制收集：把可达对象复制到新空间。
    • 分代收集：基于多数对象很快死亡的经验，把堆分代管理。

    与作业的联系¶

    作业中的 x86-64 汇编注释对应编译系统后半段：高级语言经编译、汇编、链接后成为可执行程序。函数参数寄存器、返回值寄存器、栈帧建立和恢复，都属于 ABI 与运行时约定。

    理解这些内容有助于解释：

    • 为什么函数返回值在 eax/rax。
    • 为什么递归调用要保存返回地址。
    • 为什么链接器需要符号表。
    • 为什么目标文件不能直接当最终程序运行。

    典型题型¶

    1. 写出 C 程序从源文件到运行的流程。
    2. 区分编译、汇编、链接、装入。
    3. 解释静态链接和动态链接。
    4. 说明目标文件中符号表和重定位信息的作用。
    5. 解释 JVM、字节码和即时编译。
    6. 说明垃圾收集的可达性思想。

    易错点¶

    • 编译器不负责把所有库函数代码都找齐，链接器负责符号解析和合并。
    • 目标文件不是可执行文件，通常仍含未重定位地址和外部符号。
    • JVM 执行字节码不等于只能解释执行，热点代码可即时编译。
    • 垃圾收集回收的是不可达对象，不是“不再使用但仍可达”的对象。

    • 能否解释动态库为什么可被多个进程共享？
    • 能否说明 GC 如何从根集合出发？

    第 12 章 面向对象语言的编译¶

    学习定位¶

    本章在教材中属于扩展章节，但如果课程实践涉及 Java/C++/面向对象语义，就很有用。重点理解对象、类、继承、封装、动态派发如何影响类型检查、运行时布局和代码生成。

    对象和类¶

    类描述对象的字段和方法。对象是类的实例，运行时通常包含：

    • 字段数据。
    • 指向类信息或虚函数表的指针。
    • 运行时类型信息。

    字段访问可以看作基地址加偏移：

    x.f = *(base(x) + offset(f))

    继承¶

    继承让子类复用父类字段和方法。编译器需要安排对象布局，使父类字段在子类对象中也能按一致方式访问。

    单继承较简单：子类对象通常以前缀形式包含父类部分。

    多重继承更复杂：对象可能含多个父类子对象，方法调用时可能需要调整 this 指针。

    信息封装¶

    访问控制如 private/protected/public 多数在编译期检查。运行时代码通常不再反复检查普通访问权限。

    封装影响语义分析：编译器要知道当前访问位置是否允许访问某字段或方法。

    方法调用¶

    方法调用分为静态绑定和动态绑定。

    静态绑定：编译期确定调用哪个函数。

    动态绑定：运行期根据对象真实类型决定调用哪个方法。实现常用虚函数表。

    虚函数表思想：

    对象 -> vtable 指针 -> 方法入口地址数组

    调用 obj.m() 时：

    t1 = obj.vptr
t2 = t1[offset(m)]
call t2

    类型检查¶

    面向对象语言常有子类型规则。若 Dog 是 Animal 的子类，则 Dog 对象可在需要 Animal 的地方使用。

    赋值规则可写成：

    E.type <: T
----------------
T x = E 合法

    其中 <: 表示子类型关系。

    继承的编译方案¶

    单一继承中，父类字段偏移保持不变，子类新增字段追加在后面。方法表中，重写方法覆盖父类槽位，新增方法追加槽位。

    这样父类引用指向子类对象时，仍能按父类布局访问字段和调用方法。

    典型题型¶

    1. 说明对象运行时布局。
    2. 解释动态绑定和虚函数表。
    3. 判断子类型赋值是否合法。
    4. 说明继承如何影响字段偏移和方法表。

    易错点¶

    • 重载和重写不同：重载看参数签名，重写看继承关系中的同签名方法替换。
    • 动态派发针对方法调用，不是所有字段访问都动态查找。
    • 子类对象能当父类用，不代表父类对象能当子类用。
    • 多重继承可能需要 this 指针调整。

    自测清单¶

    • 能否画出一个对象加虚函数表的布局？
    • 能否解释为什么重写方法要占用原槽位？
    • 能否判断 Animal a = new Dog() 与 Dog d = new Animal() 哪个合法？

    第 13 章 函数式语言的编译¶

    学习定位¶

    本章是扩展章节。若时间有限，掌握函数式语言和命令式语言在运行时上的关键差异即可：函数是一等值，变量绑定更强调不可变，闭包和环境是核心。

    函数式语言特点¶

    函数式语言常见特征：

    • 函数是一等值，可以作为参数、返回值、变量值。
    • 变量绑定通常不可变。
    • 递归比循环更常见。
    • 高阶函数常见。
    • 闭包用于保存函数及其自由变量环境。

    自由变量和约束变量¶

    在表达式中，由某个绑定结构引入的变量叫约束变量；没有在当前表达式内绑定的变量叫自由变量。

    例子：

    lambda x. x + y

    x 是约束变量，y 是自由变量。若这个函数被返回到外部，仍需要记住 y 的值或位置，这就是闭包要解决的问题。

    闭包¶

    闭包 = 代码指针 + 环境。

    closure = (function_code, environment)

    环境保存自由变量绑定。

    例如：

    makeAdder(y) = lambda x. x + y

    调用 makeAdder(10) 返回的函数必须携带 y=10，否则以后执行 x + y 找不到 y。

    抽象机¶

    函数式语言编译常用抽象机模型解释执行和运行时结构，例如控制栈、环境、堆上的闭包等。

    抽象机不一定是真实硬件，而是方便定义语言执行规则的目标模型。

    指令集和编译¶

    函数式语言编译器需要处理：

    • 表达式求值。
    • 函数定义和应用。
    • 环境建立。
    • 闭包构造。
    • 变量寻址。
    • 尾调用优化。

    尾调用优化很重要：若函数最后一步是调用另一个函数，则可复用当前栈帧，避免递归过深。

    典型题型¶

    1. 判断自由变量和约束变量。
    2. 解释闭包为什么需要环境。
    3. 说明函数作为返回值时运行时要保存什么。
    4. 解释尾调用优化的意义。

    易错点¶

    • 函数值不只是代码地址，还可能需要环境。
    • 自由变量不是全局变量，它只是没有在当前函数内部绑定。
    • 闭包环境保存的是函数执行所需的外部绑定。
    • 尾递归可优化成类似循环，但前提是递归调用在尾位置。

    自测清单¶

    • 能否找出 lambda x. lambda y. x + y + z 中每层的自由变量？
    • 能否解释 makeAdder 为什么返回闭包？
    • 能否说明尾调用为什么能复用栈帧？

    编译原理考前总复习¶

    一张总图¶

    源程序
  -> 词法分析：正规式、NFA、DFA、token
  -> 语法分析：CFG、FIRST/FOLLOW、LL、LR、分析树
  -> 语义分析：符号表、作用域、类型检查
  -> 中间代码：三地址码、回填、数组地址、过程调用
  -> 优化：DAG、数据流、活跃变量、到达定值、循环优化
  -> 目标代码：基本块、流图、寄存器、指令选择
  -> 运行：链接、装入、栈、堆、运行时系统

    必背但不要死背的定义¶

    • token：词法记号，通常含种别和属性值。
    • 正规式：描述词法模式。
    • DFA：确定有限自动机，适合扫描器实现。
    • CFG：上下文无关文法，描述程序嵌套结构。
    • FIRST：某符号串能推出的开头终结符。
    • FOLLOW：某非终结符后面可能出现的终结符。
    • 综合属性：从子节点向父节点传。
    • 继承属性：从父节点或左兄弟传。
    • 活动记录：一次过程调用的运行时栈帧。
    • 三地址码：最多两个源地址和一个结果地址的中间代码。
    • 基本块：单入口、单出口的顺序代码段。
    • 到达定值：某定值能否沿路径到达某点且未被覆盖。
    • 活跃变量：变量当前值以后是否可能被使用。

    高频手算题流程¶

    token 流¶

    1. 从左到右扫描。
    2. 关键字、标识符、常量、运算符、界符分清。
    3. 标识符和常量写属性值。

    FIRST/FOLLOW¶

    1. FIRST 先处理终结符和 epsilon。
    2. 产生式从左到右看，遇到不能推出 epsilon 的符号就停。
    3. FOLLOW 开始符号先放 $。
    4. A -> alpha B beta：把 FIRST(beta)-epsilon 加入 FOLLOW(B)。
    5. 若 beta =>* epsilon，把 FOLLOW(A) 加入 FOLLOW(B)。

    LL(1) 表¶

    1. 对 A -> alpha，看 FIRST(alpha)。
    2. 若含 epsilon，再看 FOLLOW(A)。
    3. 一个格子多条产生式就是冲突。

    LR 项目集¶

    1. 增广文法。
    2. 从 S' -> .S 做 closure。
    3. 对每个文法符号做 goto。
    4. 归约项目按 FOLLOW 或展望符填动作。
    5. 检查移进/归约、归约/归约冲突。

    三地址码¶

    1. 表达式先按语法树顺序生成临时变量。
    2. 数组地址记得乘宽度。
    3. 布尔表达式优先用短路跳转。
    4. 控制流用标签。
    5. 过程调用用 param 和 call。

    数据流¶

    到达定值：

    IN[B]  = union OUT[pred]
OUT[B] = gen[B] union (IN[B] - kill[B])

    活跃变量：

    OUT[B] = union IN[succ]
IN[B]  = use[B] union (OUT[B] - def[B])

    最容易丢分的点¶

    • 把词法错误、语法错误、语义错误混在一起。
    • FIRST/FOLLOW 中误把 epsilon 加入 FOLLOW。
    • 消除左递归后语言变了。
    • LL(1) 表中忘记 epsilon 产生式要按 FOLLOW 填。
    • LR closure 忘记对点后的非终结符展开。
    • 数组地址计算忘记乘元素宽度。
    • 布尔表达式破坏短路语义。
    • 死代码删除删掉了有副作用的语句。
    • 把动态链和静态链混淆。
    • 把 C 的指针传参误认为引用调用。
